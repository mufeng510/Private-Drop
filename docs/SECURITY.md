# 安全说明

> 安全是本项目的核心要求（taskbook 26）。本文描述设计上的安全模型、**需要验证**的防护点，以及安全审查要求。文档不等于已验证事实；请结合代码审查与测试结果阅读。

## 1. 安全模型

- **单用户**：只有一个管理员，没有注册、没有多租户、没有对外分享。所有设备共享同一消息空间。
- **数据主权**：数据库、附件、临时分片、配置、日志都留在用户自己的 NAS；不经任何第三方云存储或外部数据库（taskbook 22）。
- **纵深防御**：公网场景下依次是 Cloudflare Access（边缘身份）→ Tunnel 加密通道 → **应用自身鉴权**（强制、独立）。任何一层被绕过，其余层仍应阻止未授权访问。
- **最小权限**：容器以非 root（UID 10001）运行；镜像只含两个静态二进制与运行所需的最小系统工具。

## 2. 身份与会话

- 密码使用 **Argon2id**（golang.org/x/crypto）加盐哈希存储，不明文、不进日志。
- 支持 **TOTP**（RFC6238）与 **Passkey/WebAuthn**；管理界面额外要求 Passkey 或 TOTP 二次验证。
- 会话令牌在数据库中以哈希形式存储；支持登录有效期配置、主动退出、远程注销与设备撤销。
- 登录有速率限制与失败事件记录；初始化向导仅局域网可访问，完成后永久关闭，禁止抢注。
- **公网代理下的初始化防护（已实现）**：带 `X-Forwarded-For` / `CF-Connecting-IP` / `X-Real-IP` 且来自非受信代理的初始化请求一律拒绝（fail closed）。经 Tunnel/反向代理部署时必须设置 `TRUSTED_PROXY_CIDRS=代理源IP段`，应用才会依据 XFF 判断真实客户端是否为公网，从而阻止公网抢先初始化。
- **必须验证**：撤销设备后该设备的所有会话立即失效；Websocket 建连校验会话令牌。

## 3. 设备授权

三种模式：不限制、白名单、新设备需已有设备审批（站内批准或一次性授权码）。设备可重命名、远程退出、撤销授权。新设备登录、授权、撤销都记入安全事件/审计日志。

## 4. 访问控制与文件安全

- 除初始化状态与登录外，所有 API 需鉴权；**所有文件预览、下载、缩略图、ZIP 打包、站内链接复制都必须鉴权**，且不得产生公开永久链接。
- 附件以 **UUID** 作为实体文件名，不接受用户提供的路径；防止路径遍历、文件名注入与覆盖。
- 通过 **SHA-256 去重 + 引用计数**管理实体文件：删除消息只减引用；回收站/收藏引用仍有效；只有 `ref_count == 0` 且无有效上传任务时才物理删除，避免误删其他消息引用的文件。
- ZIP 下载需校验成员名称，防止 `../` 路径穿越（Zip Slip）。
- 上传：校验 MIME 与大小、限制并发；服务端记录分片状态，支持清理过期临时文件；上传期间消息被删除/过期需取消任务并清理分片。

## 5. SSRF 与链接解析

链接预览必须严格防止 SSRF：禁止访问 localhost、内网/私有 IP、NAS 内部服务、云元数据地址、非法协议；防 DNS 重绑定与重定向绕过；设置超时、响应大小限制与安全过滤。解析失败不影响消息发送。**此项属于高优先级安全测试**。

## 6. 日志与审计

- 审计记录：登录、新设备授权/撤销、安全设置修改、删除数据、清空回收站、永久删除、密码恢复等。
- 日志**不得**包含：密码、完整令牌、Passkey 私钥、TOTP 密钥、敏感文件内容。
- 日志保留与清理策略可配置。

## 7. 部署与传输

- 公网强烈建议 Cloudflare Tunnel + Access + HTTPS，且不开放入站端口；应用鉴权仍为强制项（见 [PUBLIC_DEPLOY.md](PUBLIC_DEPLOY.md)、[CLOUDFLARE.md](CLOUDFLARE.md)）。
- 经 Tunnel/Access 转发的公网请求不得被视为局域网请求：应用仅在 `TRUSTED_PROXY_CIDRS` 命中直接对端时才信任代理头；未配置且带代理头的初始化请求被拒绝（见第 2 节）。**未在真实 Tunnel 环境验证**，部署后请自行复测。
- 认证 Cookie 设计为 `HttpOnly` / `Secure`（HTTPS 场景）/ `SameSite`，API 采用 Bearer Token；需检查 CSRF 与 XSS 面。

## 8. 安全审查要求

taskbook 26 要求对以下方面做实际审查（至少覆盖）：

```
身份认证 / 会话管理 / CSRF / XSS / SQL 注入 / SSRF / 路径遍历 /
文件上传安全 / MIME 伪造 / 下载授权 / 访问控制 / WebSocket 鉴权 /
暴力破解与登录限流 / 密码存储 / Passkey / TOTP / 设备授权与撤销 /
文件引用一致性 / ZIP 安全 / 临时文件清理 / 反向代理 / Tunnel / 初始化流程
```

自动化辅助：

```bash
go vet ./...                         # 静态检查
go install golang.org/x/vuln/cmd/govulncheck@latest && govulncheck ./...   # Go 已知漏洞
cd web && npm audit --audit-level=high                                    # 前端依赖漏洞
```

> **状态说明**：CI 中已接入 govulncheck 与 npm audit（非阻断、结果写入 Job Summary），但人工代码安全审查与渗透式功能验证仍需在代码完成后进行。请不要把“有 CI 扫描”当作“已完成安全审查”。审查结论与遗留问题应写入测试报告（见 [TESTING.md](TESTING.md)）。

## 9. 报告安全问题

如发现漏洞，请私下联系维护者，不要在公开 Issue 中披露可利用细节；修复发布后同步更新本文档与版本标签。
