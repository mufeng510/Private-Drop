# 已知限制

本文件如实列出当前设计与平台层面的限制，避免把“浏览器/代理不支持的能力”误当成应用缺陷，也避免承诺做不到的事情。

## 1. 产品定位带来的限制

- **单用户**：只有一个管理员，没有注册、多人聊天室、群聊、对外分享、细粒度角色权限或商业 SaaS 功能。所有设备共享同一消息空间。
- **无端到端加密**：数据以 SQLite + 普通文件的形式存放在 NAS 上（传输层可用 HTTPS/Tunnel 加密）。能访问 NAS 数据目录的人即可读取内容，请依赖 NAS 自身的磁盘加密与访问控制。
- **无内置备份**：不提供应用内备份（taskbook 23），必须依靠 NAS 快照/备份任务，详见 [BACKUP_RESTORE.md](BACKUP_RESTORE.md)。
- **无消息历史版本**：编辑文字消息只更新内容与修改时间，不保留历史版本，也不重置保存期限。
- **无独立重复文件清理界面**：按 SHA-256 去重与引用计数自动复用实体文件，但不提供手动“清理孤儿文件”功能。
- **搜索偏轻量**：以数据库查询/简单全文能力为主，不引入复杂索引服务；海量数据下性能取决于 NAS。
- **网页不能改 Docker 端口**：对外端口在 `.env` 的 `PORT` 配置，管理界面只做展示与说明；修改后需 `docker compose up -d` 重建容器。
- **空间警戒只提醒**：达到警戒阈值不会自动删除内容，也不会自动禁止上传（taskbook 19.1）。

## 2. 浏览器与操作系统能力差异

不同平台的浏览器能力不同，应用会尽量降级，但以下能力**无法保证在所有平台可用**：

| 能力 | 说明 |
|---|---|
| 系统分享（文字/图片/文件） | 依赖 PWA Share Target / 系统分享菜单；Android Chrome 支持较好，iOS Safari 与桌面浏览器的支持有限或需“添加到主屏幕”后才出现，且格式限制由系统决定。 |
| 拍照 / 录像后直接发送 | 依赖 `<input type=file accept=capture>` 与浏览器权限；可用格式与调用方式随设备/浏览器而异。 |
| 后台上传 / 锁屏上传 | 移动端浏览器切到后台或锁屏后，JS 任务可能被系统挂起；**请保持页面在前台直到上传完成**。断点续传可在回到页面后恢复。 |
| 剪贴板图片粘贴 | 桌面浏览器支持较好；移动端多数浏览器不支持从系统剪贴板读图片，请使用分享或文件选择。 |
| 文件选择与目录上传 | 浏览器只提供文件选择器；整目录上传取决于浏览器是否支持 `webkitdirectory` 等扩展。 |
| 在线预览 | 图片/视频/音频/PDF/TXT/MD/代码等优先支持；Office 等复杂格式视浏览器能力，无法预览时提供下载。不提供在线编辑。 |
| PWA 推送通知 | iOS 需将站点添加到主屏幕（iOS 16.4+）并授权后才能收到 Web Push；桌面浏览器权限策略各异。应用内通知中心不受此限制。 |
| PWA 离线 | Service Worker 只缓存界面资源；消息与附件需要网络，从设计上就不是离线优先应用。 |

## 3. Cloudflare / 公网上传限制

经 Cloudflare 代理（Tunnel 的 Public Hostname 必然走代理）的**单个请求体**上限：Free/Pro **100 MB**、Business **200 MB**、Enterprise 最高 **5 GB**（自助可调）。超出返回 413。

- 应用的分片上传可把每片控制在限额内（建议 8–16 MB），从而缓解应用层限制；
- 但**代理层的请求体上限、读取超时（默认 Proxy Read Timeout 125 秒）、Access 会话时长、浏览器前台状态仍然生效**；
- 因此**不能承诺公网可以上传任意大小的文件**。局域网访问不受 Cloudflare 限制。

官方来源与细节见 [CLOUDFLARE.md](CLOUDFLARE.md) 第 4 节。

## 4. 运维相关

- 容器以 UID 10001 运行；宿主机 `./data` 权限不正确会导致启动失败（见 [INSTALL.md](INSTALL.md)）。
- 镜像基础层固定到主版本标签（node:24 / golang:1.27 / alpine:3.22），未锁定 digest；追求位级可复现时应固定 digest 并记录来源。
- 数据库迁移是前向的；跨大版本回滚通常需要同时恢复数据库备份（见 [UPGRADE_ROLLBACK.md](UPGRADE_ROLLBACK.md)）。
- 本项目不内置反向代理、DDNS、证书签发；这些由 NAS/Cloudflare 侧解决。

## 5. 待验证事项（非“已支持”声明）

- WebSocket 重连补齐、上传中断恢复在各类移动浏览器上的实际表现；
- Cloudflare Access 与分片上传/同站点 Cookie 的完整联调；
- 经代理的请求 IP 不会被误判为局域网（关系到初始化入口安全）。

上述项目应在最终验收中实测，结果写入测试报告（[TESTING.md](TESTING.md)）。
